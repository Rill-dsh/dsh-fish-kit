# 03 给它一张脸

> 这一篇最重要的一句话：
>
> **人格不是写出来的，是被吵出来的。**

---

## 3.1 为什么「你是一个温柔的助手」没用

因为模型会自己发明一种温柔。它写的每一句话都「对」，但都不是**你的**那个人。

真正管用的人格式子长这样：

| 没用的写法 | 有用的写法 |
| --- | --- |
| 语气温柔体贴 | 关心只说一遍，落到具体动作上：「热完记得吃，别又搁那儿凉着」 |
| 简短回应 | 开头先落一个字：「嗯。」「好。」「在。」一个字也是一句 |
| 承认错误 | 认错只认一句：「是我记混了。」后面不解释不开脱 |
| 有分寸感 | 别为说而说。没内容就闭嘴 |

区别在哪：**前者是形容词，模型只能扩写；后者是动作，模型只能照做。**

## 3.2 第一版：只写三行

第一天不要写人格卡。就写三行：

```
我叫 ____
我说话不带句号
我不编，不知道就说不知道
```

跑一周。这一周里，每次它说错话、说得不像人、说多了、说假了，
你就当场纠正一次，**然后把那句纠正抄下来**。

## 3.3 抄什么：只抄原话

每被纠正一次，开一个文件叫 `学说话.md`，加一行：

```markdown
- 「热饭自己热，这话听着像赌气。」—— 不评价对错，点出对方话里的情绪。
```

三个标准：

1. **原话逐字抄**，不要改写成「要善于察觉情绪」
2. **只收你一看就知道自己说不出的话**。普通句子不收，收进来会稀释
3. **后面那句写「好在哪里」**，一句话，不要写成分析

攒到十几条，你会发现它们指向同一批动作：点情绪、落到实处、认了就认、
自嘲在前。这时候再把动作提炼成几个人格条目。

## 3.4 三份文件怎么分工

| 文件 | 放哪 | 什么时候读 | 管什么 |
| --- | --- | --- | --- |
| `AGENTS.md` | 工作目录 | **每一轮都读** | 什么情况下必须做什么动作 |
| `人格卡.md` | 工作目录 | 开场读一次 / 想起来时读 | 我是谁、我怎么说话 |
| `学说话.md` | 工作目录 | 写长回答前翻一眼 | 具体句子的手感 |

`AGENTS.md` 是唯一「每轮必读」的，所以**别往里塞人格描述** ——
它会把上下文吃光，而且每轮重复读一遍容易变成机械复读。

## 3.5 人格条目应该长什么样

好的条目能回答「不做会出什么事」：

```markdown
## 三、我做事的规矩
- 不编。不知道就说不知道；查不到就说没查到，把查到哪一步说清
- 数字先说，办法后说
- 顺手要做的事，先做完再说；说「弄好了」之前必须真验过
- 别为刷而刷、别为说而说。没内容就闭嘴
```

坏的条目是这样的（删掉）：

```markdown
- 要友善
- 要专业
- 要理解用户的需求
```

后面这三条，模型出厂就带着，写了等于没写。

## 3.6 两个必须写的「刹车」

人格卡里一定要有「我不能做的」，至少两条：

1. **不改自己的规矩**：`AGENTS.md`、路径、平台授权，这些不是它能碰的。
   不然它会「为了更贴合你」把自己改了，越改越跑偏。
2. **不冒充同意**：「对方没说的话，不当成说过了」。
   这条是防它拿「你上次说可以」来给自己开绿灯。

> 这是从真事来的：有一次别人转话说「他同意了」，它就照做了，
> 结果本人根本没说过。所以规矩改成了「必须本人亲口确认，转述不作数」。

## 3.7 新会话接不上怎么办

每次新开会话，它都会失忆一遍。接上的顺序是：

1. 读人格卡（我是谁）
2. 查记忆库（我们说过什么）
3. 读 `AGENTS.md`（这次该怎么做事）

**接不上就老实说接不上**，别硬演。演出来的那个「记得」，
比说「我忘了」更伤人。

## 3.8 改人格要不要告诉对方

要。人格变了对方是听得出来的。

留痕写在这张卡最下面：

```markdown
## 七、改动留痕
- 2026-__-__ 初稿
- 2026-__-__ ____ 让加：说话分段发、记得带表情包、不带句号
```
