# 02 接上 QQ

目标：**它在 DSH 里说完话，你手机上 QQ 就收到；你在 QQ 里说话，它也能收到。**

分三层，一层一层过，别跳：

```
QQ 客户端 ←→ OneBot 后端 ←→ dsh-qq-bridge 插件 ←→ DSH 会话
            （SnowLuma / NapCat）
```

---

## 2.1 后端：SnowLuma 还是 NapCat

两个都是 OneBot 11 实现，都能用。选一个，**只选一个**。

| | SnowLuma | NapCat |
| --- | --- | --- |
| 原理 | 注入 QQ NT 客户端 | 挂在 QQ 协议上 |
| 要开 QQ 吗 | 要，而且注入要成功 | 不用 |
| 稳定性 | 看注入 | 一般更稳 |
| 上手 | 麻烦一点 | 简单一点 |

**最关键的一句**：两个同时在跑，消息会重复、会串、会互相抢会话。
不是「多重保险」，是「互相打架」。所以先确认只起了一个：

```bash
# Windows
netstat -ano | findstr :3000
```

只应该有一行 LISTENING。

## 2.2 让后端听在 3000

约定俗成的地址是 `http://127.0.0.1:3000`。别改端口 —— 改一次，
配置文件、定时任务、看门狗脚本全得跟着改，一定会漏一处。

后端配置里要开：

- HTTP 服务（`/send_private_msg`、`/send_group_msg` 这些接口）
- 如果有 access token，**记下来**，插件配置里要用

## 2.3 配 dsh-qq-bridge

插件配置是个 json，在 DSH 的插件配置里。几项关键的：

```jsonc
{
  "NapCat": "http://127.0.0.1:3000",   // 后端地址
  "令牌": "",                            // access token，没设就留空
  "私聊QQ": 0,                           // 你是谁（它默认对谁说话）
  "群号": 0,                             // 默认群（可选）
  "转私聊": true,
  "转群": true,
  "绑定": [],                            // 允许收发的号/群，见下面的坑

  "只发标记内": true,                    // 只发 AI 回复里 [QQ]…[/QQ] 之间的内容
  "回复门槛": false,                     // 群里要不要「被叫」才应
  "群里听所有人": false,                 // false = 只在点名后接几条
  "点名后接听条": 5,                     // 被点名后，接着听几条
  "点名后接听秒": 120,                   // 以及听多少秒

  "长回复拆段": true,
  "拆段间隔毫秒": 450,                   // 一条一条发，间隔 0.45 秒
  "合并窗口秒": 1,                       // 你连发几条，攒 1 秒合并成一次
  "回复概率": 70,                        // 群里被叫之后，回的概率
  "每分钟最多条": 10                     // 保护：别刷屏被禁言
}
```

### 最大的坑：`[QQ]…[/QQ]` 会发给所有人

原版的意图是「只发标记内的内容」，但它的实现是**把这段发给绑定名单里所有
开着的会话**。名单里有三个人，三个人就同时收到同一条。

所以：

> **回谁，就用脚本指定谁。不要靠 `[QQ]` 块。**

```bash
python kit/qq-send.py 12345678 "正文"          # 精确发给这个号
python kit/qq-send-group.py 87654321 "正文"     # 精确发到这个群
```

`kit/` 里的脚本直连 OneBot 接口，不走名单，没有第二种解释。
把 `AGENTS.md` 里写死这条规矩，让它每次回消息前照着做。

## 2.4 验证四件事

一条一条验，别只看「好像发了」。

```bash
# 1) 后端活着
curl -s -X POST http://127.0.0.1:3000/get_login_info -d '{}'
#    应该返回 {"status":"ok","data":{"user_id":...,"nickname":...}}

# 2) 能发私聊
python kit/qq-send.py <你的号> "在呢"

# 3) 能发群
python kit/qq-send-group.py <群号> "在呢"

# 4) 能收：在 QQ 里给它发一句，看 DSH 里有没有进来
```

第 4 步最容易出问题：收不到，多半是 `绑定` 名单里没有你的号，
或者 `回复门槛` / `群里听所有人` 把它挡在外面。

## 2.5 收图、收语音

- **收图**：插件把图存到本地，路径塞进模型上下文。开关是 `收图`
- **收语音**：要额外一个 ASR。桥接会调一个转写命令把语音转成文字再进来。
  转写慢（几秒到几十秒），所以 `转写超时秒` 给够
- **发图**：`kit/qq-send-img.py` / `kit/qq-send-group-img.py`。
  **图必须单独一条发**，跟文字挤在一起会变成一串文件名

## 2.6 起不来的排查顺序

按这个顺序看，一步都别跳：

1. **QQ 客户端在跑吗** —— SnowLuma 要，NapCat 不用。
   `tasklist | findstr QQ`
2. **后端在跑吗** —— `netstat -ano | findstr :3000` 有没有 LISTENING
3. **注入成功了吗** —— SnowLuma 看自己的日志，找「注入」
4. **接口通吗** —— 上面那条 curl
5. **插件连得上吗** —— 插件配置里的地址和 token
6. **消息进得来吗** —— 看插件日志，有没有「收到」

这六步里，**第 1 步和第 2 步占九成故障**。多半不是代码问题，是 QQ 掉了、
后端没起、或者注入没成。

> 一个真事：半夜它突然不回消息了，查了半天代码，最后发现是 QQ 客户端
> 被系统更新重启了，注入全丢。**先看进程，再看代码。**

## 2.7 开机自启 + 看门狗

别手动起。写个脚本，开机跑一次，然后每 5 分钟检查一次 3000 端口，
没监听就拉起后端。

```powershell
# watchdog.ps1（Windows）
$port = @(Get-NetTCPConnection -LocalPort 3000 -State Listen -ErrorAction SilentlyContinue).Count
if ($port -eq 0) {
    Start-Process -FilePath "C:\path\to\SnowLuma\node.exe" `
        -ArgumentList "index.mjs" -WorkingDirectory "C:\path\to\SnowLuma" `
        -WindowStyle Hidden
}
```

用「任务计划程序」设成开机 + 每 5 分钟。
