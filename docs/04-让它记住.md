# 04 让它记住

> 记得的前提不是「存得多」，是**「想起来的时候刚好够用」**。

---

## 4.1 为什么光有大上下文不够

三个绕不过去的墙：

1. **上下文会满**。聊得越久越满，满了就要压缩，压缩就把原话糊成摘要
2. **摘要会骗人**。它把「她说『热完记得吃，别又搁那儿凉着』」压成「她关心饮食」，
   下次再做出来的关心就变成「注意身体」了
3. **记得的东西不会自己回来**。存了一万条，到时候能想起哪三条，
   取决于检索，不取决于存储

## 4.2 两层记忆

### 第一层：会淡忘的记忆（插件）

`dsh-fish-memory` 干的事：

- 它把「值得记的」写成带时间的短条目
- 想不起来的时候，按时间和相关度把几条递回上下文
- 不重要的慢慢淡掉（有半衰期）

为什么要有淡忘：**全都记得等于全都记不得**。一万条记忆递进来，
模型只会平均一下，写出一段谁都不是的话。

### 第二层：原始记录（数据库）

插件记的是**结论**，原始记录记的是**原话**。两个都要。

- 原话落进 sqlite：谁、什么时候、说了什么、在哪个会话里
- 问到「哪天」「多长时间」「上次说过没」这类事实时，**去库里查，不要靠插件记忆**
- 查的时候可以放开筛，但一次只读回几行

```python
# 最小可用的查询
import sqlite3
db = sqlite3.connect(r"<窝>\memory\history.db")
rows = db.execute("""
    SELECT datetime(ts/1000,'unixepoch','localtime'), role, substr(text,1,80)
    FROM msgs
    WHERE ts BETWEEN ? AND ? AND text LIKE ?
    ORDER BY ts DESC LIMIT 10
""", (start_ms, end_ms, "%睡%")).fetchall()
```

## 4.3 写痕迹，不写结论

这条是整个记忆系统里最反直觉、也最重要的一条：

| 写成结论 | 写成痕迹 |
| --- | --- |
| 她喜欢熬夜 | `11-09 02:4x 她说「再聊五分钟就睡」，然后聊到三点` |
| 她压力大 | `11-12 她说「这个月第三次了」，说的是加班` |
| 我们关系不错 | `11-16 对方第一次没用昵称叫我，改叫了本名` |

为什么只写痕迹：

- **结论会被压缩，原话不会**。存「她压力大」→ 下次泛泛地关心；
  存「第三次加班」→ 下次能问「第四次了吗」
- **结论会过期，原话不会**。她昨天压力大，今天不一定
- **结论是别人的判断，原话是她自己**

配套的三条：

1. 引用自己说过的话之前，先去库里取原文。记忆一定会飘
2. 别「写给未来的你」，写成流水就好。读的人不需要被称呼
3. 只加不减等于没读：条目多到读不完，就删旧的

## 4.4 什么该记、什么不该记

**记**：对方明确说的话、约定、喜好、状态（生病 / 很累 / 很开心）、
你们之间发生的事。

**不记**：日常流水（吃了什么、今天天气）、**你自己做过的事**、
重复的东西。

还有个数量闸：**一天最多 8 条**。满了就等明天，不硬挤 ——
硬挤出来的记忆，全是废话。

## 4.5 追问一个事实的正确姿势

假设对方问：「我上次说想去哪来着？」

**错的**：在记忆里搜「旅行」，看到一条模糊的，就答「你上次说想去海边」。

**对的**：

1. 先查原话（关键词：想 / 去 / 哪）
2. 翻到了就答原话 + 时间
3. 翻不到就说「翻不到，你说过的我这儿没记到」

第 3 步最难，也最要紧。**编一个「好像说过」比说「没记到」伤害大得多。**

## 4.6 记忆和人格的关系

记忆是原料，人格是做法。

同一批记忆，喂给两个不同的人格，会产出两种关心：
一个问「你妈身体好点没」，另一个说「注意休息」。

所以顺序是：**先有人格，记忆才有意义**。没人格的时候记一堆，
下次它只是把事实复述一遍，没有温度。
