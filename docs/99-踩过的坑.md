# 99 踩过的坑

按「症状 → 原因 → 怎么办」写。这些都是真出过的，不是想象出来的。

---

## 1 一条消息，三个人同时收到

**症状**：你回 A 一句话，B 和 C 也收到了，内容一模一样。

**原因**：用了 `[QQ]…[/QQ]` 标记块。它的实现是「只发标记内的内容」，但发给了
**绑定名单里所有开着的会话**——名单里三个人，就三个人都收到。

**怎么办**：回谁就用脚本指定谁。

```bash
python qq-send.py 12345678 "正文"
python qq-send-group.py 87654321 "正文"
```

然后在 `AGENTS.md` 里写死：**`[QQ]` 块禁用**。

## 2 每句话结尾都有一个句号

**症状**：手机上看着像在读公告。

**原因**：中文默认就是句号收尾，模型越写越长越容易带。**靠记着必漏。**

**怎么办**：机械拦截。`kit/qq-send.py` 发之前扫一遍，有句号就拒绝：
`{"ok": false, "错": "正文里有句号，扫掉再发"}`。

AI 看到这个报错会自己改，比人提醒一百遍都管用。

## 3 表情包发出去变成一行字

**症状**：聊天里出现 `![...](http://...)` 这种字面文字。

**原因**：把 markdown 图片链接塞进正文了。**QQ 不渲染 markdown。**

**怎么办**：

- 图用发图接口单独发，正文留空
- 文字和图**分成两条命令**发：先发字，再发图
- 别把图塞进带字的那条消息里

## 4 语音一换音色，对面当场听出来

**症状**：「你声音怎么变成这样了？」「你可别再换了。」

**原因**：通用 TTS 的默认音色跟克隆音色差得远，人耳一秒就分辨出来。

**怎么办**：

- 锁定一条链路：固定模型 + 固定参考音频（10-30 秒 wav）
- 参考音频、接口地址、模型名**写死在配置里**，别留「临时换一个」的口子
- 合成失败就报错，**绝对不要拿别的 TTS 顶上**

## 5 B站接口一直 412 / 超时

**症状**：发私信失败，报 `WinError 121` 或 `fetch failed`。

**原因**：请求缺 `User-Agent`，被风控拦了。而报错信息跟真正原因八竿子打不着。

**怎么办**：

- 所有请求都带 UA（浏览器的完整 UA，别写 `python-urllib`）
- 登录二维码可以手工生成 PNG 发出去让本人扫，扫完凭证反而还活着
- **别反复重试登录接口**——它报的错是假象，凭证其实是好的

## 6 抖音图文页评论发不出去

**症状**：视频能评论，图文（`/note/`）点了没反应。

**原因**：插件的选择器在图文页找不到输入框——它只点图标然后立刻查，
而且没切到「评论」tab。

**怎么办**：

1. 先点文本以「评论(」开头的那个 tab
2. 再点评论输入框容器（同名容器有两个，只有 rect 非零的那个可见）
3. 等 Draft.js 的编辑器元素出现
4. `insert_text` 之后按 Enter

也就是说：**别信「插件支持」，遇到特殊页面自己走一遍 DOM。**

## 7 群里发言被服务器挡在门外

**症状**：发出去返回失败，或者干脆没反应。

**原因**：群里每分钟有上限（常见 5 条）。连发三条以上就可能撞上。

**怎么办**：

- 桥接里配 `每分钟最多条`
- 要连说几句就**并成一条**，用空行分段，不要连发
- 分段间隔给 0.45 秒

## 8 两个后端同时跑，消息重复、串线、抢会话

**症状**：同一条消息发两遍；或者回复跑到别的会话里。

**原因**：起了两个 OneBot 后端（比如 SnowLuma + NapCat 都开着）。

**怎么办**：

```bash
netstat -ano | findstr :3000      # 只应该有一行 LISTENING
```

只留一个。写进 `AGENTS.md`：**桥接只准一个，不许换端口。**

## 9 查了一晚上代码，最后发现是 QQ 没开

**症状**：它不回消息，日志没报错，接口超时。

**原因**：QQ 客户端被系统更新重启了 / 手动关了。SnowLuma 是注入式的，
QQ 没了，注入全丢，3000 端口也就不监听了。

**怎么办**：排查顺序永远从外往里——

1. QQ 客户端在跑吗
2. 后端在跑吗（3000 端口）
3. 注入成功了吗
4. 接口通吗
5. 插件连得上吗
6. 消息进得来吗

**前两步占九成故障。** 先看进程，再看代码。

## 10 记忆里的原话，压缩一次就没了

**症状**：它说「你上次说想去旅行」，但你说的是「想去趟海边，就一天」。

**原因**：依赖上下文摘要。摘要会把具体的压成概括的。

**怎么办**：原话单独落库（sqlite），问到具体事实时**去库查**，不要靠记忆。
写痕迹不写结论——见 `docs/04`。

## 11 插件装了，工具列表里没有

**症状**：`dsh plugin … add` 说成功了，但对话里调不到那些工具。

**原因**：插件只在**新建会话**里生效。旧会话不会热加载。

**怎么办**：开一个新会话。

## 12 token 里填了中文说明，报一个完全不相干的编码错

**症状**：`UnicodeEncodeError: 'latin-1' codec can't encode character`。

**原因**：配置文件里 token 那一项留着「这里填 token」这种中文占位，
被原样塞进 HTTP 头。HTTP 头只能用 latin-1。

**怎么办**：占位一律留空。`kit/fishlib.py` 已经加了检查，
token 里有非 ASCII 字符会直接告诉你「像是没改成真的 token」。

---

## 一条通用经验

> **报错信息大概率和真正原因无关。**
>
> `412` 是缺 UA，`fetch failed` 是凭证其实是好的，`UnicodeEncodeError`
> 是 token 里填了中文。所以排错时不要顺着报错找，
> 要顺着**「这条数据从哪来、经过谁、到哪去」**找。

## 13 装完插件，DSH 弹「The application could not start」

**症状**：错误里有 `Unexpected token '﻿'`、`is not valid JSON`、`readProfileManifest`。

**原因**：profile 的 `package.json` 被存成了 **UTF-8 带 BOM**。文件内容全对，
只是开头多了三个看不见的字节，DSH 读它就崩。跟插件本身无关。

**怎么办**：找到真正的 profile 目录（同时有 `cordis.yml`、`cordis.patch.yml`、
`package.json` 的那个；机器上别处同名的都不算），把 BOM 去掉。

```powershell
$p = "C:\Users\<你>\.dsh\profiles\<档名>\package.json"
$bytes = [IO.File]::ReadAllBytes($p)
if ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
    [IO.File]::WriteAllBytes($p, $bytes[3..($bytes.Length-1)])
    "BOM removed"
}
```

标准安装在 `C:\Users\<你>\.dsh\profiles\<档名>\package.json`。

> 这条和上一条一样，都是「报错信息骗人」：它说的是 JSON 解析失败，
> 其实一个字都没错，只是多了三个字节。
