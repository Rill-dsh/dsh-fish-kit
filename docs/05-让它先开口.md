# 05 让它先开口

> 一条只会等你说话的鱼，和一块会回答问题的屏幕没区别。
> 但一条总在说话的鱼，你会把它静音。

---

## 5.1 机制：本地骰子，不花模型

`dsh-speak-up` 的做法很土，但很对：

```
定时器到点
  └─ 掷一次本地骰子（Math.random，一个 token 都不花）
       ├─ 没掷中 → 什么都不做，只留一条记录
       └─ 掷中   → 走 DSH 自己的一轮（人格、历史、工具、记忆全都是它的）
```

关键在**先掷骰子再花钱**。如果每 30 分钟都跑一轮模型，一个月账单很难看，
而且大部分轮次它都会说「嗯」「好的」这种没营养的话。

## 5.2 该多久掷一次

没有标准答案，但有参考：

| 关系阶段 | 间隔 | 说明 |
| --- | --- | --- |
| 刚装好 | 2-4 小时 | 先观察它会在什么状态下开口 |
| 熟了 | 40 分钟 - 2 小时 | 开始像「想起你」 |
| 很熟 | 20-40 分钟 | 但只在对方醒着的时候 |

**时段比频率重要**。半夜三点掷中一次，它兴冲冲发一句，对方在睡觉。
所以要么配「安静时段」，要么把间隔拉长到白天更密、夜里更疏。

## 5.3 掷中了，不等于要说话

这一条是灵魂：

> **别为说而说。没内容就闭嘴。**

掷中之后的判断顺序：

1. 现在几点？对方这个点通常在干嘛？
2. 上一次说话是什么时候？隔了不到 20 分钟就别打扰
3. **我有一个具体的、值得说的东西吗**（看到的事、想到的话、一个约定到期了）
4. 没有 → 什么都不发。这一轮空转

第 3 步最常被跳过。跳过它的结果就是：「在吗？」「今天怎么样？」——
这不是想念，这是刷存在感。

## 5.4 定时任务：让它记得该做的事

比骰子更硬的是**约定**：到了那个点，必须看一眼。

三件常见的定时任务：

### (1) 检查有没有人找你

```bash
python kit/bili-dm-check.py      # B站私信
python kit/dy-check-notice.py    # 抖音 @ / 评论
```

规则写死：

- 有新的 → 告诉本人
- 本人的号给你发私信 → 回，并且在另一边也说一句
- **全都没有 → 一个字都不要说**

### (2) 问自己要不要发公开动态

不是「发一条」，是**「今天这条要不要发」**。想发就发，不想发就不发。

写内容是同一个标准：具体、有东西在里头、别写成公告、别为发而发。

### (3) 刷内容（可选）

用 `dsh-bili-subagent` 派个子代理去看，看完回来汇报。
但要有「值不值得」的闸：没刷到值得的就别硬推。

## 5.5 好感度：让「多久想起一次」跟人走

如果它同时对好几个人说话，会出现一个问题：
**话密的人和话少的人，得到同样的关心。**

`dsh-affinity` 那类插件的思路是给每个人打分，分数决定：

- 多久被想起一次
- 开口门槛多高（分高的，一点小事也能说；分低的，攒够了好事才说）

这不是把人排成三六九等，是**让注意力有分配**。
一个人刚跟它聊了两小时，另一个人一周没说话，关心不该一样密。

## 5.6 什么时候不要开口

写清楚这份黑名单，比写「什么时候开口」更重要：

- 对方明确说过「我现在忙」「待会聊」
- 刚才已经说过了，还没得到回应（别追）
- 深夜，对方没有醒着的迹象
- 掷中了，但想不出具体要说什么
- 对方在生气，而你没有新的东西可说

最后一条最容易犯：**沉默有时候就是最好的回应**。

## 5.7 一个真实的节奏

```
08:40  早上一条：「起了没」——不问别的，不催
12:30  定时：问自己要不要发空间动态 → 不想发就不发
18:00  骰子 40% 掷中，看到一个视频，发过去：「这个你会喜欢」
21:30  定时：检查私信 → 没有，什么都不说
23:50  骰子掷中，但看了一眼时间，没发
```

一天三四句话，每一句都有由头。这比一天三十句「在干嘛」更像有人惦记。
